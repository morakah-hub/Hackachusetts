## Plan / decisions

- Stack: Python stdlib `ThreadingHTTPServer` serving a static single-page UI (plain HTML/CSS/JS, canvas plots,
  no build step, no CDN: works offline) + JSON endpoints. No new dependencies.
- One `Session` owns exactly one worker thread. That thread owns every live MuJoCo object of the active run
  *and* the OpenGL context (`mujoco.Renderer` is created, used and closed on it). HTTP threads only enqueue
  actions and read copied snapshots (JPEG bytes, telemetry copies) under a lock.
- Shared execution interface `workbench/api.py`: `RunRequest` (validated, resolved to a config dict),
  `RunStatus`, `Telemetry` (recording), `RunResult`; capability registry for scenarios x controllers x options.
  Adapters wrap the existing `SimulationRunner` (reaching) and `PickPlaceEpisode` (pick-and-place); no
  second implementation of planning, control, physics or verification.
- Commands: deterministic grammar -> the same action objects as the GUI buttons.
- Recording: sampled every 5 physics steps (10 ms) + every MPC update snapshot (bounded), saved per run
  under `results/workbench/runs/<run_id>/` (git-ignored).
