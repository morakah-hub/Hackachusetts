# v0.7 results: an interactive local robotics workbench

Branch `feature/v0.7-local-workbench` (from v0.6 `a8f63df`). User guide and learning path:
`docs/workbench-guide.md`. Progress log: `docs/research/v0.7-progress.md`.

## What was built

```
browser (static HTML/CSS/JS, canvas plots, no CDN)  <-- JSON over 127.0.0.1 -->  workbench/server.py (stdlib)
                                                                                     |
        command console (commands.py) ----\                                          |
        Python API (workbench.run_to_end) --+--> RunRequest (api.py: registry, presets, validation, resolve)
        guided experiments (experiments.py)/                 |
                                                             v
                       Session (session.py): ONE worker thread owns physics + offscreen renderer
                                                             |
                       LiveRun (runs.py) -> SimulationRunner (main.py's backend)
                                         -> PickPlaceEpisode (pick_place.py's backend)
                       Recorder -> Recording (10 ms samples, every MPC update) -> results/workbench/runs/<id>/
                       inspect.py: inspectors / explanations / pre-flight on recordings + private scratch models
```

- **Shared execution interface.** `RunRequest` is validated against a capability registry of scenarios ×
  controllers × options, with reasons for refusals. It resolves to the same configuration dictionaries the
  CLIs load (`configs/*.yaml` plus overrides). The v0.6 physics, controller and gripper settings are named
  presets (`v0.6-working`, `mujoco-default`, `v0.6-strong`, `menagerie-weak`); nothing was retuned.
- **Backend changes, all additive:**
  - `PickPlaceEpisode` gained `start/advance/abort/finish`; `run()` is exactly that loop, and the episode
    and negative-control tests are unchanged.
  - It also gained optional seeded observation noise (as `SimulationRunner` already had), a before-step
    hook (used for force pulses) and a record of the joint paths it used.
  - `pick_place_study.py` now refuses to resume a folder recorded under another commit, config or library
    version.
- **Lifecycle.** One worker thread creates, steps, renders and closes every live MuJoCo object and renderer.
  HTTP threads enqueue actions or read copies. `close()` and the Quit button stop the run and join the
  thread; the tests assert that no worker survives.
- **Rendering (embedded, no fallback needed).** `mujoco.Renderer` offscreen frames are JPEG-encoded and polled
  by the page. Measured cost per 960 × 600 frame: about 11 ms without shadows/reflections, 55–80 ms with
  them. Quality presets control them, and the worker limits rendering to about a third of its time. A
  pick-and-place episode at maximum speed went from 20.8 s to 4.5 s of wall time after this change. The
  physics timestep is never changed.

## Tests (actual output)

- `tests/test_workbench.py`: 19 passed. Covers:
  - refusals of unsupported or invalid requests (9 cases);
  - resolution to the CLI configs;
  - pick-and-place through the workbench equal to `run_case` (identical placement error and step count);
  - wall reach within 0.05 mm of `main.py`'s printed hold errors (main.py reads `site_xpos` one step late);
  - force-pulse window and clearing;
  - session run → pause → single physics step (+2 ms exactly) → stop ("stopped") → reset (t = 0) → run
    (success) → saved and reloadable;
  - configuration never changes an active run;
  - commands and GUI produce the same request;
  - Run after changed settings uses them, and idle edits preview the scene while keeping the last result;
  - the HTTP server serves the UI, returns 400 for invalid input and closes cleanly.
- `tests/test_workbench_math.py`: 8 passed (including the workspace scan). Covers:
  - the MPC inspector's objective terms plus the constant the solver omits equal ½zᵀPz + qᵀz of the
    controller's actual QP (relative 1e-7);
  - explanation and inspector numbers equal the recorded values;
  - a saved run reopens with an identical recorded moment and identical explanation;
  - the sandbox equals the closed form and the v0.6 textbook example (6 saturated steps, unconstrained
    6.434 Nm);
  - zero noise reproduces the noise-free baseline exactly, seeded noise is reproducible, and recorded q is
    the true state;
  - controllers do not see `xfrc_applied`;
  - the grip experiment keeps and explains its weak-grip failure.
- **Full suite:** see the progress log for the final count and time.

## Guided experiments (one session, one run per condition; `results/workbench/experiments/`)

| Experiment | Recorded outcome |
|---|---|
| payload, CTC without observer | carrying error 0.55 mm (0.15 kg) vs 4.22 mm (1.15 kg); placement 0.45 vs 2.87 mm |
| observer, CTC, 1.15 kg | 4.22 → 0.21 mm; placement 2.87 → 0.26 mm |
| controllers, observer on, 1.15 kg | CTC 0.21 vs MPC 0.13 mm while carrying; placement 0.26 mm both; MPC 1.8× wall time |
| contact preset, 1.15 kg | v0.6-working success; MuJoCo default cone **failure at lower** (10 mm slip in the hand) |
| grip, 1.0 kg | v0.6 gripper success; Menagerie gains **failure at lift** (rose −0.1 mm) |
| force, 30 N on the hand for 1 s, reach, CTC | 11.0 mm deflection without the observer, 1.0 mm with it |
| noise (same push; σq = 0.5 mrad, σq̇ = 5 mrad/s) | push still rejected (1.1 mm); high-frequency torque 0.69 → 1.43 Nm RMS with the observer |

These single runs agree in direction with the v0.6 study, but they are exploratory: one pose, one seed, no
statistics. The custom-scenario results claim nothing about the v0.6 benchmark.

## Demonstration

`tools/capture_workbench.py` drives the real UI in headless Chrome: it types console commands, runs a 1.15 kg
pick-and-place with torque MPC + observer, replays it, opens every inspector, runs `compare observer`, and
takes screenshots.
- Outputs: `results/workbench/screens/*.png` and `workbench_demo.webp` (about 35 s at 2.5 frames/s), both
  git-ignored.
- Four screenshots are tracked in `docs/research/figures/v0.7-*.jpg`.
- The screenshots were inspected; they led to fixing the header overflow that cut off the inspector at 1600 px.

## Not done / limitations

- **Optional stretch features not implemented:**
  - actuation-delay presets;
  - joint-space goal/preview controls.
- The bounded workspace scan was implemented: a 30 mm grid with three classes ("solution found",
  "collision-blocked", "search did not find a solution"), 0.3-0.5 s on a private model.
- **Reaching runs:** clearance is not measured; the inspector says "unavailable". Pick-and-place measures it
  every 10 ms.
- **Interface:** single-user and local. Closing only the browser tab leaves the server running until Quit or
  Ctrl+C.
- **Robot and world:** the Panda remains the only validated robot. Known world, no perception, no reactive
  avoidance, no hardware.
